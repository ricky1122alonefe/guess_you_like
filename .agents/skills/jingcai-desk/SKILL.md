# jingcai-desk · 竞彩盘口/赛前桌工作纪律

## 何时使用

- 用户要改 guess_you_like 的 AI 分析流程、**三轨盘口、欧赔轨、亚盘轨、竞彩轨**、赛前桌、对照摘要或相关 prompt。
- 用户提到「把伤停/天气/赛程放进 AI 结论」「接入外部足球分析 skill/prompt/长报告」。
- 用户想调整「谁赢·依据」卡片、三轨展示、详情页、精算师 JSON schema、竞彩推荐输出。
- 用户要求 11 点前停抓欧洲公司 / 把欧/亚/竞彩揉成单一结论 / 用欧赔方向直接写竞彩购买方向。

## 核心循环（必须遵守）

```
数学基准（必须分轨）
  → 已核验变数再研判（伤停 / 天气 / 赛程）
  → 判断仓位（倾向 / 小注 / 放弃）
```

数学基准里，**欧赔、亚盘、竞彩必须分轨计算**，不要把三条线搅拌成一个「这场会出主胜/客胜」：

- 欧赔轨：主要欧洲公司 1X2 去水隐含概率 → 参考倾向。
- 亚盘轨：主要公司让球线 + 水位 → 参考方向。
- 竞彩轨：SP / RQSP → 唯一可购结论。

泊松、同赔、Elo、EV 也只是数学基准概率/赔率价值，**不准写成「这场会出主胜/客胜/大球」**。

## 产物层级（避免与旧「三套产物」打架）

### 层 A：盘口桌（odds / actuary desk，其内分三轨）

只看：竞彩 SP、欧亚转换、分歧信号、同赔、战绩、EV。输出 `judgment`、`judgment_condition`、`result_1x2_cn`、仓位。

内部三轨：

| 轨 | 输入 | 输出 | 是否可购 |
|----|------|------|----------|
| 欧赔轨 | 主要欧洲公司 1X2（`eu_books_major` 或平博 / `eu_*` 均值） | 去水隐含概率 + 参考倾向 | **不可购**，标「参考」 |
| 亚盘轨 | 主要公司亚盘让球线 + 水位 | 让谁、深浅、水位倾向 | **不可购**，标「非竞彩让球」 |
| 竞彩轨 | SP / RQSP / handicap | 可购玩法 + 倾向/小注/放弃 | **唯一可购** |

三轨对照（代码生成，不是 LLM）：

- 三轨一致 → 竞彩轨维持其仓位建议。
- 欧/亚与竞彩方向冲突 → **只能对竞彩 size_down 或 skip**，禁止把「欧赔客胜」直接写成「去买竞彩客胜」。
- 仅缺竞彩（约 11 点前）→ 竞彩轨 `missing`，只展示欧 + 亚两轨参考，**不输出可购单**。
- 禁止把竞彩让球胜平负与亚盘 `-0.5` 混称。

实现参考：`analysis/market/three_lane.py`（已建）。产品纪律：禁止为「三轨」再调三次大模型全桌调用；
五源 `result_forecast` 可作第四参考，但**不能取代三轨分开展示**。

### 层 B：赛前桌（prematch desk）

只看已核验事实：

- 伤停/停赛：来自 `sporttery_intel.py`（体彩官方伤停 API）。
- 天气：来自 `match_agents/factor_fetch.py` + `data/match_venues.json`（Open-Meteo）。
- 赛程密度：来自 `analysis/team_form/club_form.py` 近期正赛日期。

**禁止**：读取任何赔率、盘口、投注方向；输出 `result_1x2_cn` / `recommendation` / 胜平负百分比。
无数据时维度标记为 `missing`，**禁止合理假设、推理补全**。
仅支持五大联赛（短名：英超/西甲/德甲/意甲/法甲；长名：英格兰超级联赛/西班牙甲级联赛/德国甲级联赛/意大利甲级联赛/法国甲级联赛）。日职、德乙、韩K 等返回 `available=false`。

### 层 C：伤停对照摘要（prematch vs 盘口仓位）

- **代码生成**，不是 LLM 输出。
- 动作只有三种：`hold`、`size_down`、`skip`。
- 赛前桌只能降仓或放弃，**禁止把主胜翻成客胜、大球翻成小球**。
- 与盘口桌内部三轨对照是**两张不同的卡**，不要混在一起。

## 持续抓欧洲公司（与竞彩开售无关）

- `poll_service.py` 默认抓 500.com 的 `ouzhi-{fid}` / `yazhi-{fid}`，与竞彩是否开售无关。
- 北京时间 11 点前竞彩 SP 通常没动，但欧洲公司应继续 poll，间隔更短。
- `serve.py` 本地默认可带后台 poll；Docker web 必须加 `--no-poll`，避免与独立 poll 容器双抓。
- `poll_500.py` 写入 tick 时应在 `raw_meta` 里同时写 `eu_books`（全量）和 `eu_books_major`（3～6 家主要公司），供三轨/页面直接读取。
- 禁止直连 Bet365 / Pinnacle / 威廉希尔官网或付费 API。

## `high_impact_facts` 准入白名单

只有以下已确认事实可进入 `high_impact_facts`：

1. 主力门将确认缺阵（伤病或官方缺阵）。
2. 球员明确停赛（`suspensionFlag=1` 或官方停赛名单）。
3. 极端天气：暴雨/大暴雨、风速 ≥ 40 km/h、气温 ≤ -10°C。

**以下不准进高影响**：普通伤员、出战成疑、阴天/小雨、德比战意、裁判风格、媒体消息、无官方来源的阵容。

## 禁止清单

- 禁止输出「必胜」「稳胆」「确定」「稳赢」。
- 禁止把竞彩让球、亚盘、欧赔、大小球当成同一种盘混用。
- 禁止把 DuckDuckGo / 500 有料 / 网络文章写入 `high_impact_facts`。
- 禁止用错误球场坐标拉天气；禁止用联赛默认球场代替球队真实主场（如尤文勿映射圣西罗）。
- 禁止把外部足球长报告、阵型对位、球星分析接入竞彩购买结论。
- 禁止将盘口桌与赛前桌合并到同一次模型调用。
- 禁止把三轨结论揉回一个「谁赢」结论；禁止为填满三轨各调一次大模型。
- 禁止 11 点前因竞彩未开售而停止欧赔/亚盘轮询。

## 外部 football skill / GitHub 报告处理

- 可以借鉴其「盘口类型分清」「热度≠更稳」「无来源=missing」「先确认未完赛」等纪律。
- **不允许**把外部长报告、深度分析模板、阵型对位内容直接合并进 `ai_prompt.py` 的盘口桌 prompt。
- 用户要「球星破局/战术长报告」→ 单独输出，**不接**到竞彩购买结论。

## 已知坑

- 详情页必须调用 `ensure_prematch_attached`，否则旧缓存没有 `comparison_summary`。
- `attach_prematch_and_summary` 必须带本场 `fixture_id` 与 `output_root`，否则伤停缓存找不到。
- 抓完体彩伤停后若只调用幂等的 `ensure_prematch_attached`，已有 `comparison_summary` 时不会重读最新伤停；需保证写入前重新 attach。
- `match_venues.json` 禁止把曼联/切尔西/尤文等映射到错误球场；禁止用联赛默认球场填天气。
- 500.com 庄名打码（如「威***」），识别平博/威廉/立博等必须用模糊规则，不能按完整英文名硬匹。
- 时间相关测试在 11:00 前会触发「竞彩回退显示全部」逻辑，测试需 monkeypatch 到 14:00。
